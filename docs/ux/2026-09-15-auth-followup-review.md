# Atlas Mobile 首次注册与登录体验复核

日期：2026-09-15。范围：`feature/native-team-first-flow-v1`，基线 `a2a20f549262ee5cda408e2167012b0ff7d7824d` 后的认证补丁。此次仅做中文与英文文案、源码和交互路径审查；未操作浏览器、收取邮件、输入凭据或运行 Android。不能将本报告视为真人体验或原生端到端测试通过。

结论：本次密码提示和错误分类补丁可进入真实验证。源码中未发现阻止这批修改继续验证的新问题；完整注册恢复流程和 App 发布仍未通过验收。

| 核验项 | 最终源码观察 | 判断 |
| --- | --- | --- |
| 首次进入 | 默认中文；“注册新账号”入口及独立测试账号说明可见；不承诺与正式网站账号互通。 | 文案符合当前环境边界。 |
| 密码规则 | 注册时提前显示 10–128 位提示；依次校验长度、两次密码一致；登录不套用注册长度门槛。 | 用户无需先失败才知道长度要求；不会以新注册规则挡住已有密码。 |
| 提交一致性 | 提交期间锁定输入、模式和语言；同步 ref 防重复；新提交清旧提示。 | 源码具备防重复和串状态保护；快速点击仍需设备验证。 |
| 错误恢复 | 保留 SDK 错误类型和代码，分别提供密码或邮箱错误、未验证、限流、弱密码、无网络响应的中文和英文提示。未知错误使用通用提示，不展示原始服务端消息。 | 不再把所有错误都归因于密码或网络；限流不承诺未经确认的具体等待分钟数。 |
| 注册结果 | 仅说明“注册请求已提交”，指导检查收件箱与垃圾邮件、按邮件提示完成验证，再手动返回 Atlas App，用同一邮箱和密码登录。 | 不宣称邮件已送达、验证已成功或 App 已自动登录。 |
| 未验证邮箱 | 引导完成邮件验证后手动返回 App，并避免连续重复注册。 | 给出明确下一步；实际回跳仍需验证。 |

期望的真实验证顺序：进入中文登录页 → 切换注册 → 理解密码要求并提交一次 → 实际收到邮件 → 打开验证链接并看见可信的成功或失败结果 → 手动返回 App → 用同一邮箱和密码登录 → 首页成功读取当前账号的数据。后四步无法由本次源码审查证明。
